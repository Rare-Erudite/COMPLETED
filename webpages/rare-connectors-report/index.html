03OAuth connectors — real flow, honest status

The OAuth catalogue covers the services you listed (Google Gmail/Drive/Calendar/Sheets/Docs/Photos/Maps, Slack, Notion, Dropbox, OneDrive, Teams, Jira, Linear, Figma, Spotify, YouTube, X, Reddit, Discord, Trello, Airtable, Stripe, HubSpot, Salesforce, Shopify, Zoom, Calendly, Todoist, Asana, ClickUp, Miro, Canva, Zendesk, Intercom, Mailchimp, WordPress, Vimeo, PayPal, Twitch, Steam, Evernote, Monday, Basecamp, Coda, Ghost, Medium, Unsplash, Pexels, Giphy, Cloudinary, Imgur, Sentry, Datadog, PagerDuty, DigitalOcean, Cloudflare, AWS, Azure, GCP, Docker, Zapier, Make, n8n, IFTTT, Home Assistant, Hue, Google Home, Alexa, Postman, Adobe, InVision, Zeplin, Razorpay, Paystack, Flutterwave, WooCommerce, Substack, Fitbit, Strava, Google Analytics, Facebook, Instagram, LinkedIn, TikTok, Pinterest, Snapchat, QuickBooks, Xero, CircleCI, Harvest, AssemblyAI, remove.bg, HF Inference, Okta, Auth0, Snowflake, BigQuery, SonarCloud, LaunchDarkly, Typeform, Semantic Scholar, Crossref, OpenAlex, arXiv, PubMed, and more).

  • The flow is real. POST /api/connectors/:id/oauth/start builds the provider's own authorize URL with a signed state; the callback exchanges the code at the provider's token endpoint and immediately runs the connection test. Verified: with client credentials present, Google and Slack produce correctly-formed authorize URLs; a bogus state is rejected; a missing code is rejected.
  • Tenant-hosted services work. Shopify, Zendesk, Ghost, AWS, n8n, Home Assistant, WooCommerce, Weaviate, Qdrant, Kubernetes, Okta, Auth0 and Snowflake take a tenant value that is substituted into every URL. Verified: shopify with tenant my-store → https://my-store.myshopify.com/admin/oauth/authorize…; okta with acme → https://acme.okta.com/oauth2/v1/authorize…; without a tenant it refuses with a clear message.
  • Nothing is faked. A connector with no token shows Needs OAuth and a working Authorise button. Two generic entries (OpenAPI/GraphQL) that used placeholder endpoints were removed rather than listed as if they worked.
What needs you: each OAuth provider requires an app registered once with that provider, and its client id/secret set on the server (e.g. GOOGLE_CLIENT_ID/GOOGLE_CLIENT_SECRET, SLACK_CLIENT_ID/SLACK_CLIENT_SECRET). That is a fact of OAuth, not a gap in the code — the flow is implemented and tested; it cannot complete without the app registration. The UI states this on each connector.
